# Verification Receipts & Exact Tail Certificates Guide

This directory archives all full-prime cluster verification receipts and exact fixed-point MGF tail-bound certificates backing the manuscript.

## 1. `all_prime_32shot/<CONFIG_ID>/`

Each all-prime 32-trajectory certified circuit contains three JSON files:

- **`receipt.json`**: Primary 16-trajectory cluster verification receipt produced by dual independent C backends (`Gu_strict_stream_check` exact symbolic all-$2^M$ phase checker + upstream Apache-2.0 `andigu/uncompute` C `kickmix` evaluator). Cluster metadata is preserved verbatim except internal hostnames have been removed and `public_input.path` has been normalized to `data/rns_inputs/<FAMILY>.json`.
- **`holdout_receipt.json`**: Independent seed-isolated 16-trajectory holdout receipt evaluated concurrently against the **exact same unique flat-stream bytes** (`segment_hashes_sha256` and per-segment `stream_sha256` match `receipt.json` 100%). Consequently, primary + holdout verification replays twice the unique stream byte volume across 32 total trajectories without compiling a second independent stream.
- **`l1_dyadic_certificate.json`** *(authoritative)*: Standalone exact rational (`fractions.Fraction`) Proposition 3 dyadic-torus retention certificate (Eq. (A5) in the manuscript; `schema: "combined-l1-dyadic-crt-rational-certificate-v3-rigorous-diameter"`), using the full interval diameter $2^{-f} + 2^{-g_{\mathrm{gap}}}$ (and exact pinned RNS product bound) synchronized to `data/combined_frontier_49_configs.json`.

### Notes on Legacy Fields Inside Historical `receipt.json`
1. **Authoritative retention certificate**: Historical `receipt.json` files retain an embedded `l1_dyadic_certificate` field computed under an earlier `v1` midpoint-only ($0.5\cdot 2^{-f}$) formula (yielding slightly lower $\widehat{T}_{\mathrm{fact}}$ than the conservative Proposition 3 diameter bound). Always use the standalone `l1_dyadic_certificate.json` and `data/combined_frontier_49_configs.json` for authoritative manuscript figures.
2. **Legacy key name `boundary_loop1_repayment_toffoli`**: Preserved from the harness schema. On zero-segmentation-tax `rolling_anf` and `bilinear_rolling_anf` circuits (5 of 6 circuits) this value is strictly `0`; on `S3_K22_W9_COMBINED` (`packed_zero_tail`), it records the per-segment `final_phase` flush overhead (`894` extra flushes = `6,261,576` Toffolis) between the segmented verification stream (`248,339,308` Toffolis/shot, `1.0036 x 10^9` expected) and the monolithic single-flush circuit (`242,077,732` Toffolis/shot, `0.9782 x 10^9` expected).
3. **`public_input.sha256` & RNS binding**: On `S4_K22_W8_CMB` and `S4_K24_W8_OPT`, `scripts/verify_all_paper_claims.py` enforces exact byte-for-byte `public_input.sha256` equality against `data/rns_inputs/S4_P20_W8.json`. On the other four archived receipts (whose cluster runs used compact single-line JSON caches before pretty-printing `data/rns_inputs/*.json`), the verifier enforces strict ascending prime ordering (unique canonical order), deterministic Miller–Rabin primality, zero-free $3^x\bmod N$ boundary windows, capacity $L > N^W$, and exact live-recomputed $\prod p \bmod N$ (`modular_deviation_over_N` and pinned Eq. (A5)) binding against each receipt and `l1_dyadic_certificate.json`.

## 2. `same_rns_controlled_ablation/`

- **`R4B_PLUS_odd_crt_receipt.json`**: All-19,878-prime, 16-trajectory (primary-only; no separate holdout receipt) flat-stream receipt for the truncated-modulus (mod-$N_{\mathrm{trunc}}$) CRT baseline (`2,204 Q`, `f=33`) used strictly for the controlled same-RNS ablation against `R4B_PLUS_COMBINED` (`2,199 Q`, `f=33`).
- **`R4B_unsegmented_elementary_replay.json`**: Standalone unsegmented 13.31B-op elementary-gate C++17 `EGKMV1` verification receipt on the earlier odd-CRT `R4B` circuit (`2,211 Q`, 1 full-scale `MX` history and 64 input branches).

## 3. `mgf_tail_certificates/`

- **`mgf_certificates_summary.json`** (containing all 23 embedded per-family certificates): Exact fixed-point MGF Chernoff tail certificates on a $2^{-192}$ probability grid ($2^{39}$ moment LUT scale, 256-bit Taylor denominator) generated by `src/mgf_certificates/support_worker.cpp` across all 20-bit RSA-2048 prime families (Appendix C.6). Independent full-family recomputation (e.g., `977M` support entries on `S4_P20_W8`) is supported by compiling `support_worker.cpp` as documented in `README.md`.
